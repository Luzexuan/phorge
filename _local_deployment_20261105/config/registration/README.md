# 本站注册申请

用户先在本站 `/_register` 填写手机号、邮箱和姓名，三项均必填，并设置及确认个人密码。申请存为 `pending`，管理员批准前不能通过 Warden 登录，也不会创建 Phorge 账户。审核通过后可使用手机号或邮箱加密码登录；钉钉验证码通道继续保留，不使用钉钉 OAuth。

管理员在 <https://45.77.36.106/maintenance/> 的“注册审批”页面批准或拒绝申请；同一后台还提供白名单停用/恢复、个人密码设置/重置和操作记录。日常账户维护无需服务器终端，终端保留 Docker 等服务级运维。使用方法见 [网页账户维护说明](../../docs/REGISTRATION-APPROVAL.md)。

注册服务仅接收资料，不拥有 Phorge 数据库、Warden 写权限、钉钉凭据或登录密钥。它不创建认证会话。`__Host-registration_csrf` 是短期防跨站提交 cookie，不能用于身份认证。

密码为 15 至 128 个字符，支持 Unicode，保留首尾空格。`credential_hashes.py` 使用随机 16 字节盐和 scrypt（N=32768、r=8、p=3）生成哈希，最多两个并发计算；不存原始密码、不回显表单密码。注册库仅保存待审批的 `password_hash`，原有申请通过新增可空列兼容。管理员审批后，将凭据发布到 `config/passwords/users.json`；这个生效凭据文件不挂载给注册服务，后者不能自行开通或重置已有账号。

## 配置与持久化

- `python3 scripts/init-registration.py` 初始化空数据库、随机 CSRF 密钥和 `.env.registration`；重复执行保留已有数据与密钥。
- 公网只路由 `GET/POST /_register` 到 `registration:8085`。它不开放宿主机端口，也不提供公开的审批、申请列表或状态查询接口；健康检查使用容器内 `/healthz`。受权限保护的审批页面位于 Phorge `/maintenance/`，由独立私有维护服务完成操作。
- `.env.registration` 固定 HTTPS origin 和可信 Traefik 地址。`config/registration/csrf.key` 为私有文件，不提交版本管理。
- `state/registration/registrations.sqlite3` 保存申请；SQLite 使用 WAL，备份应使用 SQLite backup API，或在服务停止后备份完整目录。
- 申请的 `registration_id` 为随机 UUID，`user_id` 恒为 `reg-<同一 UUID>`。姓名、邮箱、手机号均不用于生成身份主键。

## 审核和身份边界

管理员登录网页维护后台审核，服务在共享审批锁内重新检查真实管理员身份、Warden 和 Phorge 的身份冲突，并记录操作意图与结果。公开注册服务不能调用这条管理通道。内部沿用 `scripts/approve-registration.py` 的审批校验；该脚本保留为兼容和恢复工具，不再要求普通管理员从终端审核。审批不得覆盖已有管理员、邮箱、手机号、用户名或外部身份映射。申请重复提交、与已有身份冲突均返回相同收件提示，不修改原资料。

自行填写的邮箱属于未验证信息，不能因注册、密码登录或钉钉收到验证码而变成“邮箱已验证”。新用户的邮箱和外部账户邮箱保持未验证；稳定主键绑定至明确的普通 Phorge 账户。有有效密码哈希的新申请可以独立于钉钉投递配置审批，管理员仍需核实申请者和登记资料；密码登录本身不验证手机号或邮箱所有权。网页不会为旧的无密码申请生成默认密码；未开始开户的旧申请可拒绝后让申请人重新注册，不能通过重复提交覆盖原申请密码。原钉钉/测试专用批准路径仅留在内部兼容工具中。

`+86`、`0086` 与大陆手机号统一保存为 11 位数字。其他带 `+` 的 E.164 格式可保存为待审申请；当前审批和按手机号查钉钉用户的路径只支持大陆手机号，不能把国际号码直接批准进不兼容的登录链。

`org_units` 初始为空。申请的 `org_unit_id`、`manager_user_id`、`position` 均为 NULL，表单不接受角色、部门、上级或项目权限字段。以后维护组织结构时，需要另行定义业务权限；这些占位字段现在不授予任何看板可见性。

## 限制和验证

服务检查可信代理、Host、HTTPS 转发标记、严格同源 Origin、签名 CSRF cookie 与表单 token。请求体最多 8 KiB，只接受六个单值字段（csrf、姓名、手机号、邮箱、密码、确认密码）；姓名最多 80 字符且不允许控制字符，邮箱限制与当前 Phorge 的 128 字符范围一致。每 IP 每小时最多 20 次提交，全局每小时最多 200 次，最多保留 1000 条待审申请；限流记录只保存带密钥的地址摘要。服务不记录电话、邮箱、姓名、密码、表单、cookie 或请求头。

运行 `python3 -m unittest discover -s tests/registration -v` 可验证必填项、身份冲突、CSRF、代理与同源边界、并发幂等、限流和存储边界。公网浏览器与审批验收另见 `state/acceptance/` 中的报告。
